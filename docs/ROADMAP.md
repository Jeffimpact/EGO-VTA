# Build plan after the CPU baseline

The first decision is whether a reviewer can reliably locate grasp onset and release on ordinary footage. The [baseline](../BUILD_PLAN.md) accepted one of seven selected EgoDex windows under the clean-demo gates. The sticker clip retained 291 transitions, while pour lost the hand for 36 consecutive rows. Those examples justify measuring performance by task and camera view before buying sensors or expanding collection.

The following milestones are proposed. Set task-specific tolerances before evaluating a held-out set, and record the denominator for every reported rate.

| Milestone | Work and dependency | Deliverable and exit decision |
| --- | --- | --- |
| 1. Validate on a phone | Record the same pen reach, pinch, lift, place and release with the phone fixed and then worn. Keep original MP4s. Mark event frames independently of the tracker | A small shareable episode set, annotations and a report of event-time error, valid transitions and longest gap per take. Review event overlays. Apply the existing 95% coverage and five-row-gap gates only to designated clean windows |
| 2. Account for natural failures | Add varied operators, object sizes, occlusions and viewpoints. Freeze a held-out split by recording session before tuning thresholds. Track whole-clip rejection and usable duration within valid spans | A failure table and held-out results. Distinguish missed hands from camera motion, orientation-dependent apparent size and true closure. Retain rejected examples for regression checks |
| 3. Establish metric motion | With a fixed camera, measure palm width and intrinsics and move through known displacements. Repeat with a moving camera and independent poses | A calibration bundle and plots of reference-frame translation error and drift. Choose tolerance from the intended robot task. If moving-camera error dominates, evaluate pose or depth on the same trials |
| 4. Test one wearable signal if warranted | Pick a failure from milestone 2 or 3. Compare paired RGB-only and RGB+IMU trials for head motion, or RGB+FMG for ambiguous grasp. Measure offsets, drift, missingness, capture time and cost per usable minute | Retain the added sensor only when a repeatable held-out improvement justifies calibration and operator time. Evaluate open glasses against the phone on the same protocol before committing to a rig |
| 5. Retarget and replay in simulation | Choose one robot, gripper, controller and tabletop task. Specify axes, transforms, action units, rates, saturation and gripper sign. Map a short calibrated valid span into those commands | A deterministic replay with reachability, tracking error, limit checks and grasp/release timing. Resolve replay failures before fitting a policy |
| 6. Evaluate a policy and pilot a robot | Train a small baseline from qualified demonstrations with session-level train/validation separation. Compare to scripted replay on held-out object poses, then evaluate a supervised physical pilot | Report task successes / attempts, interventions and failure categories separately for simulator and robot. Scale capture only when more data improves the chosen metric |

**Budget priority.** Use the phone and existing CPU for milestones 1–2. Measure processing time per recorded minute on the intended laptop. A wearable purchase should answer a documented sensing question, and an edge computer should address a measured throughput, latency or offline-capture requirement. Keep hardware selection independent of the choice of exporter.
